## Make 데모에서 가져온 것 / 안 가져온 것
- 가져옴: 6화면 구조와 카피(KO/EN), 카드 그리드, 결과 전/후 슬라이더 디자인, 랜드마크 EMA, 눈 구멍 복원(가림), 알파 가장자리 블러·차콜 톤(추후).
- 안 가져옴: 미리 렌더한 영상(라이브 대체용), PNG 스프라이트 4종(우리는 레퍼런스에서 뽑음), 스타일 칩 4종 고정(우리는 카탈로그가 동적).

## 라이브 전용 MVP (2026-10-31)
- 라이브 = 제품. 스타일을 바꿔 보며 내 눈에서 바로 확인하고 예약으로 넘어감. Make 프로토타입도 이 구조.
- 캡처(생성형)는 MVP에서 뺌. 코드는 고급 모드에 남겨 실험 계속 가능. 다시 넣을 조건: 라이브 품질만으로 "어울리는지" 판단이 안 된다는 테스터 피드백.

## 개인정보 (라이브 전용이라 단순)
- 사용자 얼굴: 폰 브라우저 안에서만 처리(MediaPipe + 캔버스). 서버·외부 AI로 전송 없음, 저장 없음.
- 샵 레퍼런스 사진: 서버로 전송·저장(샵 정보). Claude에 번역·눈 점 검출용으로 전송.
- 문구: "내 얼굴은 기기 밖으로 나가지 않아요. 올린 시술 사진만 서버에 저장돼요."

## 진입·제한 (아이디어 2026-10-30)
- 시판 프리셋: 무료·무제한, 구매 링크.
- 샵 디자인 올리기(남의 사진): 하루 2회 → 한도에서 [이 샵에 요청하기] (샵 리드). 스위치로 꺼둔 채 구현.
- 샵 링크(`?shop=…`): 그 샵 디자인 무제한, 예약 CTA는 샵 예약 링크.

## 구현 순서
1. index.html 을 4화면(랜딩 → 룩 → 카메라 → 라이브)으로 재배치 (기존 id·엔진 유지, 캡처 섹션은 고급 모드로). 카피는 Make KO/EN 사전 이식.
2. 라이브 품질: 핑크 톤 제품 사진 스프라이트(보라 제외 규칙), 길이 배율 기본값.
3. 하루 2회 카운터 + 샵 요청 버튼(스위치).
4. 샵 링크 파라미터 + 예약 CTA.

## 열린 결정
- 디자인 이름·샵 이름 표기(UPLOADED BY)는 샵이 올린 디자인만. 소비자가 올린 남의 샵 사진엔 이름 표시 안 함.
- 세기 슬라이더를 고객에게 보여줄지(지금은 고급 모드).

## 알려진 문제 (2026-10-30)
- (해결) EN 모드 반번역: 원인은 번역 옵저버가 파서가 추가하는 모듈 스크립트 본문 텍스트까지 번역해 JS 리터럴이 실행 전에 바뀐 것. 스크립트/스타일 안 텍스트는 제외하도록 수정(2026-10-30). 캐나다 데모는 EN 필수.
