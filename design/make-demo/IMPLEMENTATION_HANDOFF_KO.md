# Lash Pro 가상 속눈썹 구현 인수인계

## 현재 데모에서 구현한 것

현재 데모는 사용자의 원본 영상에 속눈썹을 미리 렌더링한 오프라인 프로토타입이다. 단순히 PNG 한 장을 눈 위에 회전해서 얹는 방식이 아니라, 얼굴 랜드마크를 이용해 속눈썹 뿌리를 윗눈꺼풀 곡선에 맞춰 변형한다.

- 입력 영상: `assets/video/demo-face-source-h264.mp4`
- 얼굴 모델: `assets/models/face_landmarker.task`
- 렌더러: `render_tracked_lashes.py`
- 속눈썹 소스: `assets/lashes/*.png`
- 결과 영상: `assets/video/tracked/*-tracked.mp4`
- 고객 데모 UI: `index.html`

처리 순서는 다음과 같다.

1. MediaPipe Face Landmarker를 VIDEO 모드로 실행한다.
2. 좌우 윗눈꺼풀에서 각각 9개 랜드마크를 읽는다.
3. 속눈썹 PNG의 뿌리와 끝 경계를 알파 채널에서 추정한다.
4. PNG를 8개 구간의 삼각형 메시로 나눈다.
5. 각 삼각형을 눈꺼풀 곡선과 법선 방향에 맞춰 piecewise affine warp한다.
6. 랜드마크를 시간축으로 평활화해 프레임 간 떨림을 줄인다.
7. 실제 눈의 opening polygon을 합성 결과 위에 복원해, 깜빡임과 눈꺼풀 가림을 처리한다.
8. 스타일별 높이·불투명도를 적용하고 H.264 MP4로 출력한다.

## 핵심 랜드마크

MediaPipe Face Mesh 인덱스를 사용한다.

- 화면 왼쪽 윗눈꺼풀: `33, 246, 161, 160, 159, 158, 157, 173, 133`
- 화면 왼쪽 아랫눈꺼풀: `33, 7, 163, 144, 145, 153, 154, 155, 133`
- 화면 오른쪽 윗눈꺼풀: `362, 398, 384, 385, 386, 387, 388, 466, 263`
- 화면 오른쪽 아랫눈꺼풀: `362, 382, 381, 380, 374, 373, 390, 249, 263`

현재 평활화는 이전 프레임 0.68, 현재 프레임 0.32의 EMA다. 속눈썹 뿌리는 눈꺼풀 안쪽으로 눈 너비의 약 1.8%만큼 넣어 떠 보이는 현상을 줄인다.

## 이번 품질 개선

### 색과 투명도

원본 PNG의 순검정 느낌을 따뜻한 차콜 BGR `(38, 30, 35)` 방향으로 섞었다. 얇은 털 디테일은 유지하면서 스타일별 알파를 다음처럼 낮췄다.

- Natural: 0.72
- Cat: 0.76
- Wispy: 0.70
- Volume: 0.66

알파 가장자리에 약한 Gaussian blur를 적용해 잘라 붙인 듯한 경계를 완화한다.

### 눈 깜빡임과 가림

속눈썹 합성 뒤, 윗눈꺼풀과 아랫눈꺼풀 랜드마크로 eye aperture polygon을 만든다. 해당 영역은 원본 영상 픽셀을 다시 전경으로 복원한다. 따라서 속눈썹이 홍채나 아랫눈꺼풀 위로 침범하지 않고, 눈을 감을 때 실제 눈꺼풀이 합성보다 앞에 위치한다.

## 실제 라이브 제품으로 옮길 때

데모 MP4 자체를 제품에 사용하지 말고 `render_tracked_lashes.py`의 추적·메시 변형·가림 로직을 실시간 렌더링 파이프라인으로 옮긴다.

권장 구조:

- 카메라: WebRTC `getUserMedia` 또는 네이티브 카메라 프레임
- 추적: MediaPipe Face Landmarker/Face Mesh
- 렌더링: WebGL/Three.js 셰이더 또는 네이티브 Metal/OpenGL
- 메시: 눈당 최소 9개 뿌리 점, 8개 이상의 strip segment
- 안정화: 단순 EMA에서 One Euro Filter 또는 Kalman filter로 교체
- 가림: eye aperture뿐 아니라 upper-lid skin mask와 얼굴 depth/segmentation을 함께 사용
- 성능: 추적과 렌더링을 분리하고, 랜드마크 추적은 30fps, 렌더링은 디스플레이 주사율로 보간

## 셀러 제품 이미지 처리 파이프라인

실제 셀러가 올린 착용 사진을 그대로 메시로 늘리면 안 된다. 제품별 속눈썹 자산을 먼저 표준화해야 한다.

1. 배경 제거 또는 lash segmentation
2. 좌우 눈 분리
3. 속눈썹 root curve 검출 및 기준선 정렬
4. 투명 PNG 또는 texture atlas 생성
5. 제품별 density, curl, length, outer-corner lift 메타데이터 저장
6. 공통 눈 메시 위에 텍스처로 적용

정확한 제품 재현이 중요하면 한 장의 착용 사진보다 제조사 제공 정면 제품 컷, lash map 또는 여러 각도의 자료를 받는 편이 안정적이다.

## 프로덕션 전에 추가해야 할 것

- 얼굴이 일부 가려지거나 프레임 밖으로 나갈 때 추적 신뢰도 처리
- 좌우 눈별 blink score 및 완전 폐안 상태 처리
- 고개 회전 시 3D 원근과 바깥쪽 털 길이 보정
- 조명에 따른 색·명암 적응
- 안경, 앞머리, 손가락에 대한 occlusion
- 모바일 저사양 기기 성능 측정
- 다양한 인종, 눈 모양, 쌍꺼풀/무쌍 데이터로 품질 평가
- 카메라 영상의 저장 여부와 개인정보 동의 UX

## 실행

프로젝트의 Python 가상환경과 모델·자산이 준비된 상태에서:

```bash
.video-venv/bin/python render_tracked_lashes.py
```

이 명령은 `*-tracked-raw.mp4`를 만든다. 웹 데모에는 브라우저 호환성을 위해 H.264, `yuv420p`, fast-start 옵션으로 다시 인코딩한 `*-tracked.mp4`를 연결한다.

## 현재 수준의 정의

현재 결과는 셀러 인터뷰와 제품 콘셉트 시연에 적합한 오프라인 데모다. 실제 라이브 AR의 핵심 원리와 메시 변형 구조는 검증했지만, 실시간 성능·3D 원근·복잡한 가림까지 검증된 프로덕션 SDK는 아니다.
