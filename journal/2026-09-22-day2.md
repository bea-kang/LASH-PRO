# 2일차 — 스파이크: 네 가지 방식과 실패 모음 (9/20~22)

한 페이지에 방식 A → B → C → D를 차례로 붙였다 떼었다 했다. 커밋 40개. 순서대로 쓴다.

## A. 파라미터 렌더링 (MediaPipe + 캔버스)

눈꺼풀 랜드마크 9개 위에 가닥을 그린다. 컬 J/C/D, 구간별 길이 5개, 볼륨. 레퍼런스 사진은 비전 모델이 "C컬 · 8-10-11-12-13mm · 캣 · 위스피"로 번역해서 파라미터로 넣는다.

- 처음엔 프리셋 버튼이었는데 "프리셋이 너무 못생겼다, 샵 사진 기준이어야 한다"는 피드백. 맞는 말이었다.
- 가닥이 흰자를 덮었다. MediaPipe 윗눈꺼풀 점이 눈 구멍 안쪽 가장자리라 뿌리를 바깥으로 띄워야 했다. 0.6mm는 너무 떴고 0.25mm로 맞췄다.
- 눈이 작거나 무쌍이면 항상 "덜 뜬 눈"으로 판정해서 가닥이 아래로 누웠다. 고정 비율 대신 그 사람의 최대 개방도를 기준으로 바꿨다.
- 판정: "내 눈 같지 않다. 깜빡일 때 잘못 붙인 속눈썹을 유지하는 느낌." 구조는 맞아도 게임 캐릭터 속눈썹이었다.

## B. 생성형 합성 (gpt-image-1 / Gemini)

카메라 프레임을 캡처해서 눈 주변만 자르고, 레퍼런스와 함께 이미지 편집 모델에 보낸다. 54초.

- 첫 결과는 그럴듯했는데 "새로 해석해서 붙이는 느낌". 레퍼런스를 그대로 옮기는 게 아니라 "저런 속눈썹"을 다시 그린다. 번역된 사양(컬·길이·패턴)을 프롬프트에 박아서 "해석하지 말고 이대로"라고 했더니 좀 나아졌다.
- 결과가 정지 이미지로 멈추니 "라이브로 가야지". 그래서 생성 결과에서 전/후 차이로 속눈썹만 떼어내 라이브 눈에 스티커처럼 붙이려고 했다.
- 실패 1: 얼굴에 검은 얼룩이 붙었다. 모델이 눈 주변 피부를 통째로 다시 그려서 "차이"가 속눈썹이 아니었다.
- 실패 2: 얼룩이 이마와 볼로 날아갔다. 고정 기준 삼각형을 눈 높이로 잡아서 얼굴이 멀면 삼각형이 선이 되고 변환이 폭주했다.
- 실패 3: 머리카락처럼 늘어진 줄기. gpt-image-1 출력이 항상 1536×1024(3:2)인데 납작한 크롭을 보내서 전/후가 안 맞았다.
- 판정: 생성 결과에서 속눈썹을 떼어내는 건 원리적으로 지저분하다. 접었다.

[스크린샷: 실패 1·2·3]

## C. 레퍼런스 픽셀 이식

레퍼런스 사진에서 속눈썹 픽셀을 직접 떼어(밝은 눈꺼풀 위 어두운 가닥 매팅) 내 눈꺼풀 곡선에 맞춰 붙인다. 반대쪽 눈은 좌우 반전. 0초, 0원.

- 첫 결과에서 "속눈썹처럼 보인다"가 나왔다. 하루 만에 처음.
- 눈 하나를 3점으로 한 번에 변환하니 눈 곡선이 다르면 중간이 떴다 → 12조각으로 나눠 조각마다 내 눈꺼풀 라인에 붙임.
- 눈꼬리 바깥으로 뻗는 속눈썹이 잘렸다 → 떼어내는 범위와 조각을 눈 바깥까지 연장.
- 눈썹이 같이 딸려왔다 → 열마다 위로 훑다가 빈 피부 틈이 나오면 그 위는 버림.
- 피부색 프린지(주황빛 꼬리) → 붉은 픽셀 제외.
- 한쪽 눈이 좌우 반전 → 랜드마크 번호 대신 미간과의 거리로 눈앞/눈꼬리 판정.
- 가까이·밝게 보면 "구조는 비슷, 질감은 부족". 멀리·어둡게 보면 붙임 속눈썹 띠.

[스크린샷: C 진행 과정]

### 레퍼런스 점 자동 검출

C는 레퍼런스의 눈앞·눈꼬리·뿌리 라인 3점이 필요하다. 수동 클릭은 스파이크용이고 제품에선 자동이어야 한다.

- gpt-4.1 비전에 사진 전체를 주고 좌표를 물으면 뿌리 점이 쌍꺼풀 위에, 눈꼬리가 속눈썹 끝에 찍혔다.
- 1차 좌표로 눈 주변만 크게 잘라 다시 물으니(2단계) 훨씬 나아졌고, 뿌리 라인을 점 1개 대신 5개로 받았다.
- 같은 크롭으로 gpt-4.1 / gpt-5.5 비교: 5.5가 확실히 정확. 기본 추론은 25초라 low로 낮추니 8초. 5.5-pro는 chat API에서 안 됨.
- 배운 것: 모델 등급보다 크롭이 더 컸다.

## D. 가닥 구조 추출 → 새로 그리기

C의 매팅 결과에서 가닥별 길이·각도·컬을 읽어 데이터로 만들고, A 렌더러로 내 눈에 새로 그린다. 크기·조명에 안 흔들리는 걸 기대했다.

- 구조는 읽혔는데 렌더링이 "선 긋기"라 만화 같다. 끝단·음영·뿌리 가림·광택이 없다.
- 판정: "둘 다(C, D) 퀄리티는 별로."

## 그래서 정한 것

실시간 + 사진 그대로 + 사진급, 셋을 동시에 못 가진다. 둘을 고르면 된다.

- **라이브(C)** = 고르는 화면. 길이·스파이크·스윕이 내 눈매에서 어떻게 보이는지 판단하는 용도.
- **캡처(B)** = 결과물. 라이브에 붙은 속눈썹을 겹친 화면을 보내 "배치는 그대로, 사실화만" 시킨다. 저장·공유·예약·샵 전달은 어차피 정지 이미지다.
- 실시간 사진급은 Perfect Corp가 특허 걸고 몇 년 한 영역. MVP 범위 밖.

그리고 테스트 조건. 노트북 웹캠은 눈이 60px로 잡힌다. 이 해상도에선 어떤 방식이든 스티커다. 실제 사용 조건은 폰 셀카(눈 150~300px)라서 https 터널을 열어 폰으로 보기로 했다.

## 배운 것

- "사진 그대로"는 생성이 아니라 이식이 답이었다. 생성은 해석이 들어간다.
- 라이브 고정은 앵커의 크기가 안정적이어야 한다(눈 높이 X, 눈 너비 O).
- 속눈썹 샵 사진은 밝은 눈꺼풀 + 검은 가닥이라 매팅이 쉬운 편. 도메인이 도와줬다.
- 사용자 테스트는 반드시 실제 사용 조건으로. 최악 조건으로 판단하면 방향을 잘못 잡는다.
- 하루에 API 크레딧 다 씀. gpt-5.5 비교 + 이미지 생성 = 생각보다 빠르게 나간다.
